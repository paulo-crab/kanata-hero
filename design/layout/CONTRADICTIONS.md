## Things the manifest records that no document states yet

- `Caps` is `tap-hold-press`: the hold starts as soon as another key is pressed, not only at 200 ms (kanata.kbd:170). The documents say 200 ms; the manifest has both (`timing.hold_starts_when_another_key_is_pressed`).
- Home-row holds use `tap-hold-tap-keys` with a same-hand list: a key from the same hand pressed first resolves the home-row key as a tap at once (documented in B05 as "tend to type letters"; the manifest names the hand lists).
- Space and Tab are plain `tap-hold` (no same-hand protection): a second key pressed before 220 or 250 ms types the tap then the key.
- In `nav`, only the four arrows work from Right Command; every other nav output needs the real Caps key (`requires_physical: caps`).
- `navigation-only.kbd` shares 26 aliases with `kanata.kbd`; every shared alias does the same thing (it only adds the `nop0` Space-nav marker to the nav conditions). It is not part of the game.
- Assumption (kanata semantics, not stated in the file): keys that `deflayermap numbers-symbols` does not list are transparent. If Kanata instead sends nothing for them, `b w , x` and other unlisted keys would be silent while Space is held. Recorded under `assumptions` in the manifest; worth one test on the real machine.
